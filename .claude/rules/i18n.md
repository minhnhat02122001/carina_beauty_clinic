# i18n Conventions

Three locales, declared in `src/i18n/routing.ts`: `vi` (default and source of
truth), `en`, `zh`. Every route lives under `src/app/[locale]/`.

## Two layers

Translation happens in two separate places — know which one you're touching:

- **UI chrome** (labels, headings, alt text, button copy) → `src/messages/`.
- **Editorial content** (posts, treatments, doctor bios) → localized fields on
  Sanity documents. See `.claude/rules/sanity.md`.

## Messages

- No user-facing string may be hardcoded in a component. Add the key to **all
  three** of `src/messages/{vi,en,zh}.json`, then read it with
  `useTranslations`/`getTranslations` from `next-intl`.
- A key added to one locale file but not the others is a bug, not a TODO —
  translate it before committing, or ask for the copy if unsure.
- Don't eyeball parity: `node .claude/skills/i18n-check/check-parity.js`.

## Routing

- `routing.ts` declares locales **and** per-locale pathnames. Vietnamese gets
  SEO slugs (`/services` → `/dich-vu`); `en` and `zh` reuse the internal
  English path.
- Use `Link`, `useRouter`, `usePathname`, `getPathname` from `@/i18n/navigation`
  (not `next/link` or `next/navigation`) so routes stay locale-aware.
- `src/proxy.ts` (Next 16's renamed middleware convention) runs
  `createMiddleware(routing)`, excluding `api|_next|_vercel|studio`.

## Adding a route — four files change together

1. `src/app/[locale]/<path>/page.tsx`
2. A `pathnames` entry in `src/i18n/routing.ts`. Without it the typed
   locale-aware `Link` won't accept the route.
3. The same message keys in all three `src/messages/*.json`.
4. `alternates: localizedAlternates(locale, href)` from `@/lib/metadata` in the
   page's `generateMetadata` — it builds canonical + hreflang + `x-default`.
